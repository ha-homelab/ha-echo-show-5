# Documentation languages and translation policy

The English [README](../README.md) and detailed English guides are the canonical technical documentation. The [Russian](../README.ru.md), [German](../README.de.md), [Spanish](../README.es.md) and [French](../README.fr.md) READMEs provide translated entry points with equivalent coverage of purpose, prerequisites, ordered setup, limitations and links. They are reader guides, not line-by-line translations of every historical test record.

## Five documentation languages, four runtime locales

- **Documentation entry points:** English, Russian, German, Spanish and French.
- **Detailed technical content:** the runbooks, repository-hosted [wiki](wiki/Home.md), source comments and [SVG diagrams](assets/README.md) remain in English. Each translated README states this scope and links to the canonical procedure.
- **Implemented clock-UI catalogs:** English, Russian, German and Spanish, selected through the display's `locale` setting. The current two-device deployment retains English and 24-hour formatting. **French is not an implemented runtime catalog.**
- **Upstream interfaces:** this project does not promise translated Android, Companion, VACA, Jitsi or player interfaces. Those applications have their own localization support.
- **Voice:** speech recognition, conversation language, TTS voice and wake-word models are selected independently. Changing the README language or clock locale does not install a speech model, change the HA pipeline or translate a spoken training phrase.

The [runtime localization guide](wiki/Localization.md) and [display integration](../integrations/show5-display/README.md) describe `locale`, `hour12`, fallback behavior, translated status/accessibility strings and operator-supplied labels. Documentation coverage must not be used as evidence of runtime support.

The documented dual-wake pair remains **“Привет, мышка” + “Hey Jarvis”**, at a shared **0.35** threshold, regardless of the language used to describe it. Preserve these exact phrases in translations. A model being configured or loaded does not establish reliable spoken recognition.

## Updating translated entry points

1. Change the canonical guide and English overview first. Preserve model restrictions, the after-unlock/before-format backup sequence and documented failure boundaries.
2. Update every affected translated entry point in the same PR. If a translation cannot be updated, label its outdated section visibly and link to the current English instructions; do not silently present old steps as current.
3. Keep commands, paths, API names, entity IDs, version identifiers and model codenames literal. Translate surrounding explanations naturally while preserving the actual words of a spoken training phrase.
4. Distinguish a source change, an installed artifact and an observed behavior. Do not turn a dated successful test into a present-tense guarantee. The [validation record](wiki/Validation.md) and [process/results page](wiki/Process-and-results.md) provide the shared evidence.
5. Use shared English SVG sources with useful translated image alt text in each README. Preserve the SVG's accessible title and description, visible labels and linked text equivalent. New diagrams should not require a separate copied asset for every documentation language.
6. Keep reciprocal language navigation and repository-relative links working in both a local clone and GitHub. Check all targets, UTF-8 rendering and publication inventories before publishing.

Translations should be reviewed by a fluent speaker as they evolve. Report ambiguous wording through an issue or a small pull request; never include private recordings, network addresses or credentials as examples.

## Adding a runtime locale

A translated README alone does not implement a new clock language. Add a runtime locale through the display catalog and configuration contract, cover the translated messages and formatting with the display tests, and render narrow-screen clock/status cases. Document the fallback and preserve configured labels and protocol identifiers. Record Android inspection separately from synthetic desktop rendering.

Keep the supported-language lists synchronized across the runtime guide, translated READMEs and this policy. Add a French runtime-support claim only after a French catalog and its corresponding checks actually exist.

## Review checklist

- The setup order matches the canonical runbook and includes its backup checkpoint.
- Optional components remain optional; hardware compatibility and experimental status are unchanged.
- The five README languages and four clock-UI languages are described separately.
- Local/cloud boundaries and public/private data boundaries remain explicit.
- Installed versions and lifecycle checks are distinguished from spoken-phrase, audible-response and long-duration acceptance.
- Measurements cite their source and conditions; test-count charts are not described as coverage or performance charts.
- Language navigation and local links pass `python3 scripts/check_docs.py`; SVG edits also receive visual inspection.
- A documentation-only change is validated without flashing devices, recording audio or exercising live household controls.
