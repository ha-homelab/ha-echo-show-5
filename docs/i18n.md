# Documentation languages and translation policy

The English `README.md` and detailed English guides are the canonical technical documentation. `README.ru.md`, `README.de.md`, `README.es.md` and `README.fr.md` provide translated entry points with equivalent coverage of purpose, prerequisites, ordered setup, limitations and links. They are concise reader guides, not line-by-line translations of every historical test record.

## Coverage and limits

- Available entry-point languages: English, Russian, German, Spanish and French.
- Detailed runbooks, source comments, diagrams and review discussion remain in English. Each translated README says this explicitly and links directly to the canonical procedure.
- Language navigation is reciprocal, uses repository-relative links and works in a local clone as well as GitHub.
- This is **documentation internationalization**. It does not add languages to upstream firmware, translate an app interface, install a speech model, select an HA pipeline or change a wake word. Runtime UI support belongs to each upstream app/integration.
- A voice deployment selects speech recognition, conversation language, TTS voice and wake-word model separately. Keep their tested support and acoustic acceptance distinct from translated documentation.

## Updating translations

1. Change the canonical guide and the English overview first. Preserve the model restrictions, backup sequence and documented failure boundaries.
2. Update every affected translated entry point in the same PR. If a translation cannot be updated, label its outdated section visibly and link to the current English instructions; do not silently present old steps as current.
3. Keep commands, paths, API names, entity IDs, version identifiers and model codenames literal. Preserve the actual words of a spoken training phrase, even when the surrounding text is translated.
4. Translate explanations and link labels naturally. Do not infer new hardware support or turn a dated successful test into a present-tense guarantee.
5. Keep one shared SVG for the architecture and provide useful translated image alt text. Preserve its title, description, visible labels and text equivalent in the README.
6. Check reciprocal language links, all repository-relative targets, UTF-8 rendering and any publication allowlist before publishing.

Translations should be reviewed by a fluent speaker as they evolve. Report ambiguous wording through an issue or a small pull request; never include private recordings, network addresses or credentials as examples.

## Review checklist

- The setup order matches the canonical runbook and includes its backup checkpoint.
- Optional components are identified as optional.
- Hardware compatibility and experimental status are unchanged.
- Local/cloud boundaries and public/private data boundaries remain explicit.
- New measurements cite their source and test conditions; architecture drawings are not presented as performance charts.
- A documentation-only PR is validated without flashing devices, recording audio or exercising live household controls.
